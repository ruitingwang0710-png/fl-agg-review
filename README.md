# Reviewer code and generated results

Anonymous artefact accompanying the submission *Checking the Output Does Not
Check the Aggregator*. Everything reported in the paper is regenerated by the
scripts here; no number is quoted from memory.

## Install

```bash
python -m venv .venv && source .venv/bin/activate
pip install "flwr[simulation]==1.33.0" numpy scikit-learn matplotlib
```

No network access is required at run time. The training study uses the
handwritten-digits set that ships with scikit-learn; there is nothing to
download.

## Reproducing each reported result

| Paper item | Command | Writes |
|---|---|---|
| Table 1, Table 2, §3 verdicts | `python evidence.py` | `results/summary.csv` (51 rows: 17 cases × 3 claims) |
| §3 byte-identity of the A and B bundles | `python check_ab.py` | stdout |
| §4 bit-exactness (`0x3ff0000000000000`, raw bytes) | `python bit_exact_check.py` | stdout; **asserts**, so a failure fails the run |
| Figure 1, Table 3, §4 separability | `python separability.py && python mkfig.py` | `results/separability_{random,noisefloor,constructed}.csv`, `figures/separability.pdf` |
| Figure 2, §4 reachability | `python m1_run.py && python m1_analyse.py && python mkfig_m1.py` | `m1_results/*.csv`, `figures/reachability.pdf` |
| §4 implementation-semantics paragraph ($\sqrt{\varepsilon}$) | `python m1_krumfloor.py` | `m1_results/m1_krumfloor.csv` |
| §4 retention behaviour of the framework | `python inspect_state.py` | stdout |

Optional, in the order they were originally run:

```bash
python walkthrough_1.py   # one aggregation each under FedAvg and Krum
python walkthrough_2.py   # the coincident fixture: the two rules agree bit for bit
python align_check.py     # independent NumPy implementation vs. the framework
cd coincident-app && flwr run . local-simulation --stream   # a full simulated round
```

Run time: the controlled study, the constructed configuration and the
byte-level checks are deterministic and finish in seconds. `separability.py`
takes about a minute. `m1_run.py` takes roughly ten minutes on two cores. All
seeds are fixed; re-running reproduces every table byte for byte.

## What is here

| file | what it does |
|---|---|
| `reference_krum.py` | Krum re-implemented in plain NumPy. **Imports nothing from the framework** — re-running the implementation under test would establish only that it agrees with itself. |
| `reference_rules.py` | The same for FedAvg, Multi-Krum, coordinate-wise median and trimmed mean, written from the published definitions and using different primitives where a choice exists (sort rather than partition; explicit self-removal rather than dropping the first sorted element). |
| `evidence.py` | Builds four worlds × four evidence levels plus a tampered bundle, verifies each with a blind verifier, writes `results/summary.csv`. |
| `check_ab.py` | Reports the C2 differences and whether the A and B bundles are byte-identical at each level. |
| `bit_exact_check.py` | Asserts identity of *representation*, not just of value: compares the `uint64` views and the raw bytes of the two aggregates. Equality of value is weaker — `-0.0` and `0.0` compare equal while differing in their leading bit — so this is what earns the word "bit-exact". |
| `align_check.py` | Checks the independent implementation against the framework on both rules and both fixtures. |
| `separability.py` | The substitution gap on random honest configurations, the re-implementation noise floor, and the constructed symmetric configuration. |
| `m1_fed.py` | The federated machinery for the training study: data, partitions, models, local SGD, aggregation wrappers, dispersion statistics, and the Krum selection comparison. |
| `m1_run.py` | Drives the six arms of the training study. |
| `m1_analyse.py` | All summary statistics, Spearman correlations and log–log slopes. |
| `m1_krumfloor.py` | The distance-formula probe behind the implementation-semantics paragraph. |
| `mkfig.py`, `mkfig_m1.py` | Figures 1 and 2. `mkfig_m1.py` asserts the omitted interval of its broken axis is empty before drawing it. |
| `inspect_state.py` | Row counts of every table in the framework's state store after a completed run. |
| `coincident-app/` | A minimal framework app: five simulated nodes, one round, the unmodified declared rule. |
| `evidence/` | The generated bundles. `truth.json` sits **outside** each bundle directory and is never read by the verifier. |
| `results/`, `m1_results/` | Machine-generated; not edited by hand. |

## The three claims and four verdicts

The verifier is handed a bundle directory and nothing else.

| claim | question |
|---|---|
| C1 | What does the record state was configured? |
| C2 | Does the recorded aggregate equal an independent re-performance of the declared rule on the recorded submissions? |
| C3 | Did the declared rule's code path execute? |

Verdicts: `consistent`, `contradicted`, `unable_to_determine`, `invalid_bundle`.
`unable_to_determine` is never folded into `consistent`.

Blinding is enforced rather than asserted: one test instruments every file read
performed during verification and fails if any path resolves outside the bundle;
a second fails if the verifier's source so much as names the ground-truth file.

## Environment

Python 3.11 and 3.13; `flwr` 1.33.0; NumPy 2.4.x and 2.5.2; scikit-learn 1.8.0;
Matplotlib 3.10.x. `float64` throughout, single CPU, no GPU. The controlled
study was reproduced under two NumPy versions; the training study was run under
Python 3.11.

## Limitations

Stated in full in the paper. In brief: five synthetic clients and one round in
the controlled study; one small real data set, sixteen clients and two model
families in the training study; every client in every run is honest, so this
measures what the check can see, not what a defence can stop. The runtime
execution record behind C3 is written by the same process that performs the
aggregation, so it establishes execution only if that recorder is sound and was
not bypassed.

## How this was built

The question, the separation into three claims, the verdict design, the choice
of what to measure and the stated limitations are the authors'. Parts of the
implementation were written with an AI coding assistant. Every number reported
here and in the manuscript is regenerated by the scripts in this repository.
